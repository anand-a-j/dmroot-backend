# connected_accounts

External messaging accounts (Instagram for now) that an organization has connected to DMRoot. Holds the encrypted access token used to send messages on the organization's behalf.

Migration: `XXXX_connected_accounts_create_connected_accounts.sql` (replace XXXX with the applied number).

## Columns

| Column | Type | Notes |
|---|---|---|
| id | UUID PK | Generated by the application. |
| org_id | UUID NOT NULL | FK to `organizations`, ON DELETE CASCADE (tenant erasure removes tokens). |
| connected_by_user_id | UUID NULL | FK to `users`, ON DELETE SET NULL. Display/audit only. |
| platform | VARCHAR(30) | CHECK: `instagram`. Extended by a later migration. |
| platform_account_id | VARCHAR(100) | External account ID as text. Must equal the ID Meta sends in webhooks (to be verified in Phase 6). |
| account_name | VARCHAR(150) NULL | Display name. |
| username | VARCHAR(100) NULL | Handle. |
| access_token_encrypted | TEXT NULL | Ciphertext only. NULL only when disconnected. Never selected by default. |
| token_expires_at | TIMESTAMPTZ NULL | When the token stops working. NULL when disconnected. |
| status | VARCHAR(20) | `active`, `expired`, `disconnected`. Default `active`. |
| disconnected_at | TIMESTAMPTZ NULL | Set exactly when status is `disconnected`. |
| metadata | JSONB NOT NULL | JSON object, display-only, no secrets, never filtered on. |
| created_at / updated_at | TIMESTAMPTZ | `updated_at` maintained by trigger `trg_connected_accounts_updated_at`. |

## Constraints

- `connected_accounts_platform_check`, `connected_accounts_status_check`
- `connected_accounts_platform_account_id_check`: not empty.
- `connected_accounts_state_check`: disconnected rows have no token, no expiry and a `disconnected_at`; all other rows have a token and no `disconnected_at`.
- `connected_accounts_metadata_object_check`: `metadata` must be a JSON object.

## Indexes

| Index | Purpose |
|---|---|
| `uq_connected_accounts_live_platform_account` UNIQUE (platform, platform_account_id) WHERE status <> 'disconnected' | An external account can be live in only one organization. Also used for webhook lookups. |
| `idx_connected_accounts_org_platform` (organization_id, platform) | Listing an organization's accounts. |
| `idx_connected_accounts_active_token_expiry` (token_expires_at) WHERE status = 'active' | Future token-refresh job. |

## Lifecycle

- Connect: new row, `active`.
- Reconnect by the same organization: the existing row is updated (token replaced, status `active`, `disconnected_at` cleared).
- Account live in another organization: rejected (HTTP 409).
- Expire: `active` -> `expired`; ciphertext kept so the row stays valid under the CHECK.
- Disconnect: row kept, token and expiry set to NULL, `status = 'disconnected'`, `disconnected_at = NOW()`.
- Disconnect is not erasure. No foreign key points at this table with RESTRICT, so a hard delete (deletion request) is always possible. Organization deletion cascades.

## Access token data flow (for Meta data protection assessment)

Status key: **Implemented** = in place after Phase 5. **Planned** = Phase 6.

1. **Generated.** The token is issued by Meta after the account owner authorizes DMRoot through OAuth. DMRoot does not create or see the user's Instagram password. *Planned (Phase 6).*
2. **Transmitted.** The token is received server-to-server over TLS during the OAuth code exchange. It is never sent to the browser, never placed in a URL we log, and never returned by any DMRoot API. Outbound calls to Meta send it over TLS only. *Planned (Phase 6); API-response and logging rules Implemented.*
3. **Stored.** Encrypted by the application before it reaches the database (Fernet: AES-128-CBC with HMAC-SHA256, via `cryptography` MultiFernet). Only the ciphertext is stored in `access_token_encrypted`. Encryption keys come from environment configuration (separate keys per environment, different from the JWT secret), not from the database or source control. The application refuses to start outside development without a key. The token is not stored in Redis, in Celery task arguments, or in logs; log output is redacted for `token`, `access_token`, `authorization`, `client_secret`. Background tasks receive only the connected account ID and decrypt in the worker. *Implemented.*
4. **Renewed.** A scheduled job will refresh tokens before `token_expires_at` (found via the partial index) and replace the ciphertext. If refresh fails or the token is rejected, the account is set to `expired`. Key rotation is supported by adding a new primary key to the key list and re-encrypting. *Planned (Phase 6); expiry tracking and `expired` status Implemented.*
5. **Removed.** Disconnecting nulls the ciphertext immediately. Deleting an organization deletes its rows (and tokens) through CASCADE. Copies in database backups age out under the backup retention policy. *Implemented.* Unsubscribing from Meta and the Meta deauthorize/data-deletion callbacks are *Planned (Phase 6).*
6. **Access.** Only admins of the owning organization can list, view, or disconnect accounts, and none of those endpoints return the token. Only the internal repository method `get_encrypted_token` reads the ciphertext, and only for `active` accounts.
